# ทะเบียนและเลขเอกสาร ว804

## ขอบเขต

- หนึ่งชุดคำขอมีเลข `W804-001`, `W804-002`, … ใช้ร่วมกันทั้งรายงานขอซื้อ/TOR รายงานสรุปผล และรายงานส่งใช้เงินยืม
- เลขออกจากฐานข้อมูลเมื่อบันทึกทะเบียนครั้งแรกเท่านั้น แก้ไขและพิมพ์ซ้ำคงเลขเดิม ไม่รีเซ็ตรายปี รองรับเลขเกิน 999
- เป็นทะเบียนจัดทำเอกสาร **ไม่เข้าสายอนุมัติ** และไม่สร้างรายการใน `procurement_requests` หรือ workflow
- เปิดทะเบียนจากลิงก์ใน `/requests/w804` ไป `/requests/w804/registry` ผู้ยื่นเห็นเฉพาะชุดของตน ผู้ดูแลระบบเห็นทุกชุด บัญชีต้อง active
- PDF แสดงเลขเดียวกับทะเบียนที่หัวและท้ายทุกหน้าของแบบฟอร์ม ชื่อไฟล์เป็น `W804-001-purchase.pdf`, `W804-001-summary.pdf`, `W804-001-settlement.pdf` เลขหนังสือราชการช่อง “ที่” ไม่เปลี่ยน
- หน้าเอกสารแนบต้นฉบับที่นำมาต่อท้ายไม่ถูกแก้ไขหรือประทับเลขเพิ่มเติม

## การบันทึกและไฟล์เดิม

ปุ่ม “บันทึกทะเบียน” บันทึกข้อมูลทั้ง 3 รายงาน แม้รายละเอียดสำหรับพิมพ์ยังไม่ครบ แต่ต้องมีชื่อเรื่องและข้อมูลชนิด/วงเงินถูกต้อง ปุ่ม “บันทึกและดูตัวอย่าง / พิมพ์” ตรวจข้อมูลของรายงานนั้นและบันทึกรุ่นล่าสุดก่อนเปิด PDF ถ้าบันทึกล้มเหลวจะยังไม่สร้างตัวอย่างใหม่

“ดาวน์โหลดแบบร่าง (.json)” เป็นสำเนาเนื้อหาในเครื่อง **ไม่ใช่การบันทึกทะเบียน** ไม่มีเลข/UUID ที่นำไปสวมสิทธิ์แก้ไขคำขออื่นได้ เปิด JSON เก่าในชุดใหม่แล้วบันทึกเพื่อรับเลขใหม่ หากเปิด JSON ขณะกำลังแก้ไขชุดที่มีเลข ระบบขอยืนยันแทนที่เนื้อหาชุดนั้นและยังไม่บันทึกจนกดปุ่มบันทึก หากต้องการสำเนาคนละเลขต้องกด “สร้างชุดใหม่” ก่อน

ไฟล์แนบทั้ง 3 รายงานยังอยู่ในหน่วยความจำของเบราว์เซอร์เท่านั้น ไม่อัปโหลด ไม่อยู่ใน JSON หรือทะเบียน ต้องเลือกใหม่เมื่อกลับมาเปิดคำขอ ระบบเตือนก่อนออกเมื่อมีข้อมูลที่ยังไม่บันทึกหรือไฟล์แนบ

## การเก็บข้อมูลและความปลอดภัย

Migration: `202610140003_w804_document_registry.sql`

- ตาราง `w804_document_sets` + sequence `w804_request_no_seq` แยกจาก POL-01 และ ว119
- RLS จำกัดการอ่านด้วยเจ้าของ/บทบาท active; authenticated ไม่มีสิทธิ์ INSERT/UPDATE/DELETE ตรง หรือเรียก sequence
- RPC `save_w804_document_set(record_id uuid, expected_revision integer, draft_data jsonb)` ตรวจสิทธิ์ซ้ำ คำนวณวงเงินจากรายการ และออกเลขใน transaction
- UUID สร้างครั้งเดียวต่อชุดสำหรับ retry; advisory lock ต่อ UUID ป้องกันสร้างซ้ำเมื่อส่งซ้ำพร้อมกัน เลขใช้ atomic sequence ไม่ใช้จำนวนแถว
- `revision` ป้องกันทับข้อมูลจากหลายหน้าต่าง คืน `40001` เมื่อข้อมูลล้าสมัย ผู้ใช้เก็บ JSON แล้วเปิดทะเบียนใหม่ได้ การส่ง payload เดิมซ้ำหลังคำตอบสูญหายคืนผลเดิมโดยไม่ออกเลขซ้ำ
- Sequence รับประกันไม่ซ้ำ ไม่รับประกันไร้ช่องว่างเมื่อ transaction ล้มเหลว ห้ามลด/reset ตัวนับเพื่ออุดช่องว่าง
- Server ตรวจ Zod schema ทุกฟิลด์และขนาด JSON 250 KB; SQL ตรวจสิทธิ์ รูปแบบหลัก ขนาดสูงสุด 260 KB (เผื่อช่องว่างของ jsonb) และวงเงินไม่เกิน 50,000 บาท

## เปิดใช้จริง

1. ตรวจ backup ปัจจุบันและใช้ migration นี้หลัง migrations เดิม โดยไม่ลบ/เปลี่ยนเลข POL-01 หรือ ว119
2. Deploy โค้ดหลังสร้างตาราง/RPC และ schema cache reload สำเร็จ
3. ใช้บัญชีทดสอบที่ได้รับอนุญาตใน staging ตรวจบันทึกครั้งแรก/แก้ไข/เปิดจากทะเบียน/PDF ทั้ง 3 รายงานก่อนใช้ production
4. แบบร่างเก่าเป็นไฟล์ในเครื่อง ไม่มีแถว W804 เดิมที่ต้องเปลี่ยนเลข ให้นำเข้าเมื่อผู้ใช้ต้องการ ไม่สแกนหรือนำเข้าไฟล์ส่วนตัวอัตโนมัติ
5. หากต้องย้อน UI ให้คงตารางและ sequence ไว้ ห้ามลบข้อมูลหรือใช้เลขที่เคยออกซ้ำ

การเพิ่มโค้ดและไฟล์ migration ใน repository ไม่เท่ากับรัน migration หรือ deploy บน production
