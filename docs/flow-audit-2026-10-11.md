## ประเมินคุณภาพ 5 มิติ

คะแนน 0–4 ด้านที่มีหลักฐานเป็นเพียงการประเมินชั่วคราวจากโค้ดและตัวอย่างหน้าที่ทดสอบ ไม่ใช่คะแนนรับรองทั้งเว็บไซต์ จึงไม่รวมเป็นคะแนนเต็ม 20

| มิติ                     | คะแนนชั่วคราว  | หลักฐาน/ข้อจำกัด                                                                                                                     |
| ------------------------ | -------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Accessibility            | ยังไม่ให้คะแนน | ตรวจตัวอย่าง labels, สถานะข้อความ และ Escape; ยังไม่ได้ตรวจ contrast ทุกคู่, screen reader, keyboard ทุก flow หรือรับรอง WCAG 2.2 AA |
| Performance              | ยังไม่ให้คะแนน | build ผ่าน แต่ไม่มี Lighthouse, Core Web Vitals, load test หรือ profiling production                                                 |
| Theming                  | 3/4            | ส่วนใหม่ใช้ token/องค์ประกอบเดิม; มี utility สีเฉพาะจุดและค่าแบบพิมพ์ ไม่ได้ยืนยัน dark-mode suite                                   |
| Responsive               | 2/4            | desktop/mobile ตัวอย่างส่วนใหญ่ผ่าน; ยังมีกรณี root scrollWidth ของฟอร์ม POL-02 หลัง resize ที่ต้องตรวจต่อ                           |
| Implementation integrity | 3/4            | คงเอกสาร/สายงานเฉพาะผลิตภัณฑ์และแยกสิทธิ์ใน server/SQL; review ส่วนแก้ผ่าน แต่ยังต้องยืนยัน integration จริง                         |

ความสอดคล้องของระบบออกแบบผ่านในขอบเขตตัวอย่างที่ตรวจ: ใช้กระดาษอุ่น/graphite/ส้ม กรอบเหลี่ยม ตารางงาน และข้อมูลพร้อมการกระทำถัดไป ตัว detector หนึ่งรอบพบ advisory 2 จุดเรื่อง `#000` ใน CSS แบบพิมพ์เดิม จัดเป็นบริบทเอกสาร ไม่พบเหตุให้เปลี่ยน token ทั้งระบบ และไม่ใช่ข้ออ้างว่าตรวจคุณภาพครบทุกหน้าแล้ว

- หลังแก้ metadata เอกสารรอบสุดท้าย lint, TypeScript และ Vitest เต็มชุดผ่าน 504 tests ใน 47 files; production build, format check และ diff check ผ่าน พร้อม targeted tests แบบพิมพ์ 29 tests

| ลำดับ        | ประเด็น                                            | ผลกระทบและการติดตาม                                                                                                                                                                                               |

| ต้อง triage  | Dependency advisories                              | `npm ci` รายงาน 10 high advisories จาก lockfile เดิม ยังไม่วิเคราะห์ exploitability หรือ upgrade ไม่ใช่หลักฐานยืนยันช่องโหว่ที่โจมตีแอปได้ทุกตัว                                                                  |

หน้าพิมพ์มี canvas เอกสารกว้างกว่าจอมือถือโดยตั้งใจ; ต้องแยกจาก root overflow ที่ไม่ตั้งใจ ไม่จัด finding จากขนาด A4 เพียงอย่างเดียว การค้นหา/รายงานจำกัด 1,000 รายการล่าสุดที่มองเห็น (ค้นหาต่อประเภท, รายงาน POL-01) ไม่ใช่การสรุปข้อมูลทั้งหมดเมื่อเกินเพดาน

ยังไม่มี API/credentials สำหรับ SSO บุคลากร ระบบงบประมาณ email/LINE และผู้ให้บริการ e-sign จึงไม่ได้เพิ่ม integration เหล่านี้หรือสร้างข้อมูลอำนาจอนุมัติขึ้นเอง ผลรอบนี้ไม่ใช่คำยืนยันว่าเว็บไซต์สมบูรณ์ 100% หรือผ่าน WCAG

## ขั้นนำขึ้นใช้งาน

1. Review SQL และเตรียม backup/แผนย้อนกลับตามกระบวนการหน่วยงาน ยืนยัน migrations ก่อนหน้าใน staging
2. Apply `202610110003_payment_revision_flow.sql` แล้ว `202610110004_resume_procurement_drafts.sql` ใน staging และ deploy โค้ดรุ่นเดียวกัน
3. ใช้ผู้ยื่นและผู้พิจารณาอย่างน้อยสองบัญชีตรวจอ่านข้ามบัญชี บันทึกร่าง แนบ/เปิดไฟล์ ส่งกลับพร้อมเหตุผล แก้ไข ส่งใหม่ขั้นเดิม พิจารณาต่อ และตรวจ PDF ที่ดาวน์โหลด
4. ตรวจ mobile overflow, keyboard/contrast และ performance เพิ่ม เติมผลทดสอบตามจริง แล้วใช้ `$impeccable audit` และ `$impeccable polish` ปิดรอบเฉพาะจุด
5. ขออนุมัติ release ตามกระบวนการก่อนดำเนินการ production; รอบนี้ **ไม่ได้เปลี่ยน production DB, push หรือ deploy**

วิธีติดตั้ง runtime SQL ทดสอบแบบแยกส่วนอยู่ที่ [tests/sql/README.md](../tests/sql/README.md) ห้ามนำ secret หรือข้อมูลส่วนบุคคลจริงลง fixture/เอกสารผลทดสอบ
