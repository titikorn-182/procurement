# คำขอหลักการ POL- ภายนอก

`/requests/pol-external` อยู่ถัดจาก ว804 สำหรับผู้ยื่นคำขอและผู้ดูแลระบบที่เปิดใช้งานอยู่ ผู้ใช้ยืนยันแบบ A (5 ขั้นตอน) และสายอนุมัติ POL-01 เดิม เมื่อ 11 ตุลาคม 2569

## ขอบเขตการออกแบบเฉพาะหน้า

- สืบทอดสี ตัวอักษร ปุ่ม และกรอบเหลี่ยมจาก `DESIGN.md` เดิม ไม่สร้างระบบออกแบบหรือแก้ token ส่วนกลาง การยืนยันแบบ A อยู่ที่ `.impeccable/mocks/pol-external/option-a.json`
- ส่วนหัวของหน้าประกอบด้วยชื่อคำขอและปุ่มตัวอย่าง / พิมพ์ PDF ตามด้วย 5 ขั้นตอน: ข้อมูลคำขอ → รายการพัสดุ → งบประมาณ → เอกสารแนบ → ตรวจสอบและส่ง เลขขั้นตอนและเครื่องหมายถูกหมายถึงความคืบหน้าการกรอก ไม่ใช่ผลอนุมัติ
- แสดงแผงกรอกเพียงขั้นตอนเดียว โดยขั้นแรกไม่มีตารางรายการหรือรหัสงบประมาณ ปุ่มย้อนกลับ/ถัดไปอยู่ท้ายแผง และปุ่มแบบร่างอยู่ด้านล่างแยกจากการส่งคำขอ
- จอเล็กเรียงขั้นตอนแนวตั้ง; ตั้งแต่ `sm` เป็น 5 คอลัมน์ ช่องข้อมูลทั่วไปและงบประมาณเป็น 2 คอลัมน์ตั้งแต่ `md` ตารางรายการคงความกว้างขั้นต่ำ 960px ภายในพื้นที่เลื่อนแนวนอนที่รับโฟกัสคีย์บอร์ดได้
- ใช้ข้อความแจ้งข้อผิดพลาดพร้อมย้ายโฟกัสไปยังข้อความนั้น เปลี่ยนขั้นตอนแล้วโฟกัสหัวข้อขั้นตอน และคงคำอธิบายแบบร่าง/การส่งคำขอให้ชัดเจนโดยไม่พึ่งสีอย่างเดียว
- แบบพิมพ์ใช้ตราจริง `public/ubu-emblem.png` และ TH SarabunPSK จากส่วนพิมพ์กลาง บน A4 ขอบใน 14mm ตัวเนื้อหา 16pt หัวเรื่องเฉพาะแบบ 19pt/23pt และตาราง 14pt ค่าของหัวเรื่องและสัดส่วนคอลัมน์เป็นข้อกำหนดเฉพาะแบบนี้ ไม่ใช่ type scale ใหม่ของหน้าจอ

## ข้อมูลและกระบวนการ

- แหล่งข้อมูลแบบพิมพ์: PDF `แบบฟอร์มจ้าง-อปท.pdf` ที่ผู้ใช้แนบ เป็นแบบโครงการบริการวิชาการจากแหล่งทุนภายนอกของคณะรัฐศาสตร์ มหาวิทยาลัยอุบลราชธานี
- เก็บเป็น `formType: standard`, `formVersion: 1` พร้อม `externalPol01` รุ่น 1 ใน JSON เดิม ไม่สร้างตาราง เลขที่ หรือสายอนุมัติใหม่ จึงไม่ต้องมี migration
- ใช้ RPC เดิม: create draft → upload attachments → submit; returned requests update/resubmit ในเลขคำขอเดิม พร้อมตรวจเจ้าของและสถานะ ไม่เปิดสิทธิ์เพิ่มเติม
- เก็บช่องส่วนราชการ โทรศัพท์ เลขที่/วันที่หนังสือ เรียน งาน/สาขา หน่วยงานพัสดุ วิธีซื้อ/เช่า/จ้าง ข้อความ TOR และหมายเหตุรายรายการใน metadata; ข้อมูลรายการ วงเงิน งบประมาณ และเอกสารใช้ตารางเดิม
- เช่าใช้ kind `hire` ในกระบวนการเดิม แต่เก็บ method `rent` และแสดง “ขอเช่า” ในหน้ารายละเอียด
- การแก้ไขแบบส่งกลับคงชนิดแบบภายนอกและหมายเหตุ ไม่เปลี่ยนเป็นแบบทั่วไป เอกสารแนบเดิมเก็บไว้ และเพิ่มไฟล์ได้
- ไม่ใส่รายชื่อผู้ลงนาม/กรรมการอัตโนมัติในแบบภายนอก เพราะไม่มีช่องเหล่านี้ใน PDF ต้นฉบับ การอนุมัติจริงยังอยู่ใน workflow/audit เดิม

## แบบร่างและพิมพ์

- ปุ่มบันทึกแบบร่างดาวน์โหลด JSON ลงเครื่อง (ไม่ส่งคำขอ ไม่เก็บไฟล์แนบ) เปิดกลับผ่าน schema จำกัด 250 KB ไม่มี localStorage
- ฟอร์มเริ่มด้วยช่องรายการ วัตถุประสงค์ และรหัสงบประมาณว่าง ข้อมูลตัวอย่างเป็น placeholder เท่านั้น
- จำนวน/ราคาใช้ทศนิยมไม่เกิน 2 ตำแหน่งและตรวจขอบเขต numeric ของฐานข้อมูล ราคาศูนย์ต้องกรอกเอง
- พิมพ์ A4 ด้วย TH SarabunPSK ตาม PDF ต้นฉบับ ตารางมีหมายเหตุ หัวตารางซ้ำเมื่อหลายหน้า ยอดรวมตัวเลข/ตัวอักษร และรหัสงบประมาณ 4 ช่อง
- ก่อนส่ง preview ระบุฉบับร่าง หลังส่งใช้ข้อมูลที่บันทึกจริง รองรับดาวน์โหลดรวมเอกสารแนบด้วยระบบเดิม
- หลังสร้าง draft บน server แล้วจะล็อกข้อมูลในหน้าเพื่อป้องกันการ retry ด้วยข้อมูลที่ต่างจากคำขอที่บันทึกไว้; หากเครือข่ายขัดข้องให้ตรวจสถานะคำขอก่อนส่งซ้ำ

## การตรวจสอบ

`pol-external*.test.ts` ครอบคลุม schema, numeric precision/overflow, empty values, JSON drafts, saved metadata, PDF content, authorization, existing RPC routing และป้องกันการเปลี่ยน subtype ระหว่างแก้ไข
การทดสอบ UI/PDF ใช้ข้อมูลสมมติในเครื่อง ไม่ส่งคำขอหรือแก้ฐานข้อมูล production
