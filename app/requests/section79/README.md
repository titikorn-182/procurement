# คำขอซื้อ/จ้าง ข้อ 79 วรรค 2

เส้นทาง `/requests/section79` อยู่ใต้เมนู ว804 ผู้ใช้ยืนยันวันที่ 11 ตุลาคม 2569 ให้จัดทำ บันทึกแบบร่าง และพิมพ์ก่อน โดยไม่เชื่อมสายอนุมัติ

## ขอบเขตและข้อมูล

- ใช้ PDF ที่ผู้ใช้แนบ `ขออนุมัติเบิกจ่าย ตามระเบียบฯ ข้อ 79 วรรคสอง .pdf` เป็นแม่แบบ: บันทึกข้อความ เหตุจำเป็นเร่งด่วน หลักฐาน จำนวนเงิน/ผู้รับเงิน งบประมาณ และความเห็น/ลงนาม 6 ส่วนพร้อมรหัสงบประมาณ
- ตัวแบบระบุวงเงินไม่เกิน 500,000 บาท จึงตรวจกรอบนี้ก่อนพิมพ์ ไม่ใช่การยืนยันสิทธิ์หรือการตีความเกณฑ์กฎหมาย
- ชื่อบุคคล รายการ ร้านค้า จำนวนเงิน และรหัสงบประมาณเริ่มว่าง ไม่ใช้ค่าตัวอย่างเป็นข้อมูลจริง ผู้จัดทำต้องตรวจชื่อ/ตำแหน่งผู้ปฏิบัติหน้าที่ ช่องความเห็น ช่องเลือกผล และลายมือชื่อใน PDF ว่างไว้เสมอ
- ผู้ยื่นคำขอและผู้ดูแลระบบที่เปิดใช้งานเท่านั้นผ่านการตรวจสิทธิ์ที่หน้า server
- ไม่สร้างคำขอ เลขเอกสารอัตโนมัติ งานอนุมัติ หรือข้อมูลใน Supabase และไม่ต้องมี migration
- แบบร่าง JSON มี format/version เฉพาะ จำกัด 250 KB เปิดกลับได้แม้ยังกรอกไม่ครบ ไฟล์แนบไม่รวมอยู่ใน JSON; ไม่มี localStorage
- PDF/JPG/PNG รวมท้าย PDF ได้บนเครื่องผ่านระบบพิมพ์เดิม ไฟล์ต้นฉบับไม่ถูกแก้ไขและไม่อัปโหลด

## แบบ A ที่ผู้ใช้ยืนยัน

สืบทอด Document Control Center เดิม ไม่เปลี่ยน DESIGN.md ส่วนกลาง ภาพที่อนุมัติคือ `.impeccable/mocks/section79/option-a.png` พร้อม sidecar `approved: true` (seed `7a7231f5`)

1. เหตุจำเป็นและหลักฐาน: ข้อมูลบันทึกข้อความสองคอลัมน์ รายการ เหตุจำเป็น และใบเสร็จ/ใบส่งของ
2. ค่าใช้จ่ายและงบประมาณ: จำนวนเงิน ผู้รับเงิน ปีงบประมาณ แหล่งเงินและรหัสตามแบบ
3. ผู้ลงนามและเอกสาร: ชื่อ/ตำแหน่ง 6 ส่วน ไฟล์แนบ แล้วตรวจสอบ/พิมพ์ PDF

| องค์ประกอบภาพที่อนุมัติ        | การนำไปใช้จริง                                                              |
| ------------------------------ | --------------------------------------------------------------------------- |
| Sidebar และเมนูใต้ ว804        | AppShell เดิม/ไอคอนเดิม เพิ่มเฉพาะลิงก์ใหม่ ไม่จำลองตราหรือจัดเมนูอื่นใหม่  |
| ส่วนหัวและปุ่มบันทึก/เปิด      | Semantic HTML และปุ่มส่วนกลาง; บอกชัดว่าเก็บ JSON ลงเครื่อง                 |
| แถบสามขั้นตอน                  | ปุ่ม HTML เรียงตาม DOM, aria-current, ตรวจข้อมูลก่อนข้ามไปข้างหน้า          |
| แบบบันทึกข้อความสองคอลัมน์     | CSS grid, จอเล็กเรียงหนึ่งคอลัมน์ และช่องเหตุผลเต็มความกว้าง                |

| แบบพิมพ์                       | HTML/CSS A4, ตรามหาวิทยาลัยจริง และ TH SarabunPSK; เนื้อหายาวแบ่งต่อหน้าได้ |

ข้อผิดพลาดมีข้อความและย้ายโฟกัสให้ผู้ใช้ เลขขั้นตอนหมายถึงการกรอก ไม่ใช่การอนุมัติ

## ภาพและพฤติกรรมที่ส่งมอบ

- ใช้ Sarabun และลำดับหัวข้อ/เนื้อหาจากส่วนกลาง พร้อมแผ่น graphite พื้นกระดาษอุ่น สีส้มสำหรับขั้นตอนปัจจุบัน/ปุ่มหลัก และกรอบเหลี่ยมไม่มีเงา; `DESIGN.md` และ `.impeccable/design.json` ยังคงตรงกับระบบเดิมและไม่ได้แก้ไข
- จอ desktop ตั้งแต่ 1280px จัดป้ายกำกับข้างช่องและลดช่องว่างเฉพาะขั้นตอนแรก ให้เห็นเหตุจำเป็นและต้นส่วนหลักฐานในพื้นที่ทำงาน โดยยังรักษาช่องควบคุมสูงอย่างน้อย 44px; จอเล็กเรียงป้ายเหนือช่องตามลำดับ DOM
- แบบพิมพ์ใช้ TH SarabunPSK เนื้อหา 16pt หัวบันทึก 28pt ตารางความเห็น 15pt และตารางรหัส 14pt บน A4; สีดำ `#000` คือหมึกตามเอกสารต้นแบบ ไม่ใช่ชุดสีส่วนกลางใหม่
- ตารางความเห็น 6 ส่วนเริ่มหน้าใหม่และแบ่งต่อได้เป็นแถว เนื้อหายาวไหลต่อหน้า ส่วนหัวบันทึกและตรามหาวิทยาลัยยังแสดงในการพิมพ์ผ่านเบราว์เซอร์
- คำเตือนออกจากหน้าครอบคลุมลิงก์ปกติ การแทนแบบร่าง และ `beforeunload` ตามที่เบราว์เซอร์อนุญาต; Navigation API ป้องกัน back/forward ภายในเอกสารเดียวกันเฉพาะเหตุการณ์ที่ยกเลิกได้ เบราว์เซอร์เก่าหรือการย้อนกลับแบบ escape traversal อาจไม่ถามยืนยัน จึงต้องตรวจไฟล์ที่ดาวน์โหลดเป็นสำเนาถาวรก่อนออกเสมอ ไฟล์แนบต้องเลือกใหม่เมื่อเปิด JSON

## บันทึกตรวจรับ

ผลตรวจรอบสุดท้าย: **ship**; ข้อสังเกตเรื่องส่วนหัวพิมพ์ผ่านเบราว์เซอร์และความหนาแน่น desktop แก้ไขครบแล้ว ไม่มีการบันทึกข้อมูลธุรกรรมหรืออัปโหลดไฟล์ไปภายนอก

- PDF ข้อมูลปกติ 2 หน้า; รวม PDF แนบ 1 หน้าได้ทั้งหมด 3 หน้า; กรณีข้อความยาว 3 หน้า; native print 2 หน้า
- ไม่พบ horizontal overflow ที่ความกว้าง 320, 390, 768, 1024 และ 1600px
- การทดสอบ model, access และ document ผ่าน 53 รายการ; ชุดทดสอบทั้งหมดผ่าน 465 รายการใน 43 ไฟล์ และ lint ผ่าน
- หลักฐานภาพ: `output/pdf/section79-desktop-step1.png`, `output/pdf/section79-mobile-step1.png` และ `output/pdf/section79-native-print-1.png`

บันทึกนี้เป็นข้อกำหนดเฉพาะหน้าที่สืบทอดระบบเดิม ไม่ยกระดับรูปแบบสามขั้นตอน ความหนาแน่นของแบบฟอร์ม หรือรูปแบบเอกสารราชการเป็นกฎใหม่ทั้งโครงการ
