# POL-02: คำขอเบิกจ่าย

ส่วนขยาย flow ภายในระบบเดิม สืบทอด [DESIGN.md](../../DESIGN.md) และบริบท [PRODUCT.md](../../PRODUCT.md) โดยไม่สร้าง token หรือ visual identity ใหม่

## เส้นทางใช้งาน

| เส้นทาง                | หน้าที่                                                                     |
| ---------------------- | --------------------------------------------------------------------------- |
| `/payments`            | รายการตามสิทธิ์ ค้นหา กรองสถานะ และแบ่งหน้า; โหลดไม่เกิน 1,000 รายการล่าสุด |
| `/payments/new`        | สร้างจากคำขอหลักการที่เข้าเกณฑ์ ใช้ฟอร์ม POL-02 เดิม                        |
| `/payments/[id]`       | รายละเอียด รายการเงิน เอกสารแนบ ขั้นตอน และประวัติการพิจารณา                |
| `/payments/[id]/edit`  | เจ้าของที่ active ทำฉบับร่างต่อหรือแก้ไขรายการส่งกลับ                       |
| `/payments/[id]/print` | พิมพ์/เตรียม PDF จากข้อมูลที่บันทึก พร้อมเลขคำขอและสถานะ                    |

`[id]` ใน URL นี้คือ `payment_no` ไม่ใช่ UUID; สร้างลิงก์ผ่าน `paymentHref()` เพื่อ encode เลขเอกสาร

## การเปลี่ยนสถานะและข้อมูล

- ฉบับร่าง → ส่งพิจารณาขั้นแรก → พิจารณาตามขั้นที่กำหนด
- ส่งกลับ → เจ้าของแก้ไขและส่งใหม่ → **กลับขั้นผู้พิจารณาเดิมที่ส่งกลับ** ไม่เริ่มสายใหม่
- ส่งกลับและไม่เห็นชอบต้องมีเหตุผล; สิทธิ์การตัดสินใจยืนยันใน RPC ไม่อาศัยการซ่อนปุ่มเพียงอย่างเดียว
- `save_payment_request_revision` ตรวจเจ้าของ สถานะ และ `expected_updated_at` เพื่อป้องกันการเขียนทับข้อมูลรุ่นใหม่ พร้อมเก็บ snapshot ใน `payment_revisions`
- เอกสารแนบเดิมคงอยู่จนผู้ใช้เลือกนำออกและบันทึก; การเปิดไฟล์ยังผ่านสิทธิ์ของระบบ
- แบบพิมพ์ใช้ข้อมูลบันทึกและ snapshot ยอด ณ ส่งคำขอเมื่อมี ข้อมูลเก่าที่ไม่มี snapshot ไม่ควรถูกตีความเป็นหลักฐานยอดย้อนหลังที่รับรองแล้ว

โค้ดหลัก: `data.ts` อ่านข้อมูล/RLS, `payment-model.ts` แปลงข้อมูลและแบบพิมพ์, `[id]/actions.ts` เรียก RPC พิจารณา, `new/actions.ts` จัดการบันทึก/ส่งคำขอ

## รูปแบบหน้าจอที่สืบทอด

พื้นกระดาษอุ่นและกรอบเหลี่ยมใช้ชุดสีเดิม ปุ่มส้มระบุการกระทำหลัก อักษร Sarabun ใช้ลำดับหัวเรื่อง/เนื้อหาเดิม ตัวเลขเงินจัดแบบ tabular; แบบพิมพ์ใช้ TH SarabunPSK ตาม component เอกสารเดิม

รายการเป็นตารางงาน รายละเอียดแบ่งข้อมูลกับแถบตัดสินใจบนจอกว้างและเรียงลงบนมือถือ ตารางรายการเงินเลื่อนภายในแนวนอนได้ สถานะแสดงข้อความชัดเจน ไม่ใช้สีล้วน ทั้งหมดเป็นการประยุกต์ “Orange Is a Command”, “Square Dossier” และ “State Must Read Twice” จากระบบออกแบบเดิม

ไม่ยกระดับค่าเฉพาะแบบพิมพ์ เช่น สีดำสำหรับเอกสาร ให้เป็น token ใหม่ของทั้งเว็บไซต์ และไม่ถือ overflow ที่ยังตรวจไม่จบเป็นกติกาออกแบบ
